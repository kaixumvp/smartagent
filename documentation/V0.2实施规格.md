# V0.2 实施规格（Implementation Spec）

> 对应《版本规划.md》V0.2「能力版」。目标：**从「写死一个 Agent」到「业务方组装 Agent」，平台初具通用性**。
> 依赖：V0.1。技术栈延续 V0.1（Python 3.11 + FastAPI + LangGraph + LiteLLM + SQLAlchemy 2.0 + Pydantic v2 + PostgreSQL + Redis），本期新增 **pgvector**（长期记忆起步）与 **python-jose/pyjwt**（JWT 鉴权）。

---

## 1. 范围（做什么 / 不做什么）

**做**：
- **插件体系**：统一 `Plugin` 协议 + `manifest` 标准 + 生命周期 + 插件 SDK（本期落地 `tool` / `skill` 两类）
- **Skill Manager**：Skill 注册 / 语义化版本 / Agent 绑定（`skill@version`），四种形态（prompt / function / flow / agent）
- **Tool Manager**：扩展 MCP 工具 + HTTP(OpenAPI) 工具 + 权限管控（最小权限 + 越权拦截）
- **Brain**：Working Brain 完整化 + 长期记忆起步（Vector Memory 基础写入/召回 + 会话固化）
- **Gateway**：多租户隔离 + JWT 鉴权 + 限流（令牌桶）
- **IAM**：RBAC（用户/角色/权限）+ 资源级授权（Grant）+ 高危工具人工确认（HITL-lite）
- **Runtime**：SubAgent 调用（父-子嵌套，`agent-skill` 落地）

**不做（后续版本）**：
- Memory Graph / 记忆图谱、遗忘 / 元记忆评分 / `reflect`（V0.3 Cognitive Brain 完整）
- 知识回退（Brain 不全 → Knowledge）与 RAG / KG（V0.3）
- checkpoint 持久化、Retry（退避/熔断）、Pause/Resume、节点级 HITL（V0.3 Workflow Engine）
- 全链路可观测 / Console / 评测（V1.0 / V1.1）
- 工具沙箱（subprocess/容器隔离，本期高危外部工具用「最小权限 + 前置审批」兜底）

## 2. 与 V0.1 的变更概览（迁移）

| V0.1 | V0.2 | 迁移策略 |
|------|------|----------|
| `Tool` 独立协议 | `Tool` 成为 `Plugin` 子类型 | `Tool` 类增加 `kind="tool"` 与 `manifest`，`run` 收敛为 `invoke` |
| `agents.config.tools: []` | `agents.config.plugins: []` | 读取时兼容 `tools`，写入统一 `plugins`；一次性迁移脚本把 `agent_tools` 转成 `plugins` |
| `agent_tools` 关联表 | 弃用（绑定并入 `plugins`） | 保留表不删除，新增数据不再写；提供 `scripts/migrate_agent_tools_to_plugins.py` |
| `tenant_id` 恒为 `'default'` | 真实多租户 | 新增 `tenants` 表，所有资源按 `tenant_id` 行级隔离，中间件注入 |
| 无鉴权 | JWT 鉴权 | 新增 `auth` 路由 + 鉴权中间件；`/health` 与 `/auth/login` 免鉴权 |
| `tools` 表只有 builtin | 增加 `mcp` / `http` 类型 | `tools` 表加 `endpoint` / `config` / `requires_approval` / `tenant_id` |
| Working Brain 仅缓存 | Working 完整 + 会话固化 | 会话结束异步固化到 Vector Memory |
| `runs.status` 无 `awaiting_human` | 支持 `awaiting_human` | 高危工具前置审批门使用 |
| 单体代码库 | 业务层 + Agent 框架层（smartagent-core）双包 | `plugins/skills/tools/memory/core` 等运行时能力迁入框架层，业务侧经 `adapters/` 实现端口 |

## 5. 插件体系（Plugin System）

### 5.1 统一插件协议（`plugins/base.py`）

```python
class PluginManifest(BaseModel):
    name: str
    version: str
    kind: str                 # tool | skill | knowledge | model | memory | node（本期实现 tool/skill）
    description: str = ""
    parameters: dict = Field(default_factory=lambda: {"type": "object", "properties": {}, "required": []})
    permission: str = "read"  # read | write | admin
    requires_approval: bool = False
    dependencies: list[str] = []
    tags: list[str] = []

class InvokeContext(BaseModel):
    tenant_id: str
    user_id: str | None
    run_id: str | None
    trace_id: str | None
    session_id: str | None

class Plugin(Protocol):
    kind: str
    manifest: PluginManifest

    async def setup(self, config: dict) -> None: ...      # 初始化（懒加载时调用一次）
    async def invoke(self, ctx: InvokeContext, **kw: Any) -> Any: ...  # 调用
    async def teardown(self) -> None: ...                 # 卸载
```

> V0.1 的 `Tool.run(**kwargs)` 平滑收敛为 `Plugin.invoke(ctx, **kwargs)`；`Tool` 保留一个 `run` 别名做兼容。`kind` 枚举预留 `knowledge/model/memory/node`，本期仅实现 `tool` 与 `skill` 两类，其余版本接入同一协议（见技术方案 4.12.2）。

### 5.2 插件引用（ref 解析，`plugins/manifest.py`）

- 格式：`{kind}:{name}@{version}`，`@version` 可省略（取 `is_latest`）
- 示例：`tool:calculator`、`skill:refund@1.2.0`、`skill:script_writer@2`
- `Agent.config.plugins` 元素两种写法（等价）：

```jsonc
{"type": "tool", "ref": "tool:calculator"}
{"type": "skill", "ref": "skill:refund@1.2.0", "config": {"max_amount": 500}}
```

### 5.3 生命周期

`注册（DB/manifest）→ 懒加载（首次 setup）→ 运行（invoke）→ 停用 → 升级（新版本写入 + 切 is_latest，运行中实例不重启）→ 卸载（teardown）`

- 插件实现从 DB（`tools` / `skills` 表）加载，不在代码里硬编码；builtin 工具也走表注册
- 懒加载：`PluginRegistry.resolve(ref)` 首次命中才 `setup`，结果按 `ref` 缓存；版本升级后缓存失效重建
- 热更新：切换 `is_latest` 不重启服务，新 run 装配时取新版本

### 5.4 插件 SDK

第三方按 `Plugin` 协议实现 + `PluginManifest` 声明能力与权限，注册进 `tools`/`skills` 表即被 Agent 引用（对应技术方案 4.12.4）。SDK 提供 `register_tool()` / `register_skill()` 便捷装饰器，本期不建插件市场。

## 6. Skill Manager

### 6.1 四种形态（`skills/base.py`）

| 形态 | `type` | `body` 内容 | `invoke` 行为 |
|------|--------|-------------|---------------|
| **prompt-skill** | `prompt` | `{"template": "..."}`（含占位符） | 渲染模板注入上下文，供 LLM 参考（不执行代码） |
| **function-skill** | `function` | `{"source": "..."}`（Python 函数源码） | 隔离加载函数并执行，入参按 `parameters` 校验 |
| **flow-skill** | `flow` | `{"graph_spec": {...}}`（预定义子图） | 装配 LangGraph 子图并运行，返回最终结果 |
| **agent-skill** | `agent` | `{"agent_ref": "agent_xxx"}` | 调用子 Agent（复用 Runtime 图，见 §11） |

### 6.2 注册与绑定

- 注册：`POST /v1/skills`，写入 `skills` 表一条（一个版本）；同名新版本写入新记录并更新 `is_latest`
- 绑定：`Agent.config.plugins` 里 `{"type":"skill","ref":"skill:name@version"}`
- 版本灰度：`ref` 显式 `@version` 即锁定；不写版本随 `is_latest` 漂移（灰度 = 只改 `is_latest` 指向）

### 6.3 Skill 与 Tool 的边界

Skill「重」——封装上下文与流程，内部可调用多个 Tool；Tool「轻」——原子能力。Decide 节点统一把两者视为「可选能力」，execute 节点按 `kind` 分派（见 §11.2）。

## 7. Tool Manager 扩展

### 7.1 工具类型

| 类型 | 来源 | 注册方式 | 说明 |
|------|------|----------|------|
| `builtin` | 平台内置 | 迁移迁移（V0.1 已注册 calculator/http） | 走 Plugin 协议 |
| `mcp` | MCP 工具服务器 | `POST /v1/tools` 填 `endpoint`（MCP server URL） | 用 MCP 客户端协议发现/调用工具 |
| `http` | OpenAPI 描述的 REST | 填 `endpoint`（OpenAPI spec URL）+ `config.auth` | 解析 OpenAPI → 生成 `parameters` JSON Schema |

### 7.2 权限管控（最小权限）

- 每个 Tool 声明 `permission`（`read`/`write`/`admin`）+ 可选 `requires_approval`
- 执行前 `PermissionManager.check()`（§10.3）：
  - `permission=read`：人人可用
  - `permission=write`：需 Grant 授权
  - `permission=admin` 或 `requires_approval=true`：需 Grant 授权 **且** 触发高危审批（HITL-lite，§10.4）
- 越权调用 → `deny` → 工具执行返回失败 + 审计留痕（拦截）

### 7.3 观测埋点（V0.2 基础）

每次调用记录 `tool_name / 入参 / 出参 / 耗时 / 是否成功` 到 `run_steps`（V0.1 已落数据，V0.2 补 `action` 填 `tool:name` 或 `skill:name`）。

## 8. Brain：Working 完整 + Vector Memory 起步

### 8.1 分层（V0.2 只做两层，Memory Graph 是 V0.3）

```
Memory Manager（门面：write / recall / consolidate）
    ├── Working Brain（Redis，会话级）           —— V0.1 已有，本期完整化
    └── Vector Memory（pgvector，长期语义记忆）   —— 本期起步
        （Memory Graph 记忆图谱 —— V0.3）
```

### 8.2 统一接口（`memory/` 内抽象）

```python
class MemoryEntry(BaseModel):
    id: str
    tenant_id: str
    user_id: str | None
    content: str
    importance: float = 0.5
    confidence: float = 0.5
    source: str = "working"      # working | vector
    created_at: datetime | None = None

class IMemory(Protocol):
    async def write(self, session_id: str, message: dict) -> None: ...                 # Working
    async def recall(self, tenant_id: str, user_id: str, query: str, top_k: int = 5) -> list[MemoryEntry]: ...  # Vector top-k
    async def consolidate(self, session_id: str, tenant_id: str, user_id: str) -> None: ...                     # 会话固化
```

> `sufficiency` / `forget` / `reflect`（重要性评分、遗忘、充分度评估）属 V0.3 完整 Cognitive Brain，本期不实现。`importance`/`confidence` 字段本期先落默认值，供 V0.3 演进。

### 8.3 会话固化 Consolidation（`memory/consolidator.py`）

```
会话结束（run 完成/失败/纠错）──异步触发──► 抽取高价值片段
        │（Redis Streams + 简单 worker，V0.2 不引入 Celery）
        ▼
  片段 ──embedding──► vector_memories 写入
        （同片段按 tenant/user/session 去重，避免重复固化）
```

- **固化内容**：会话中的用户偏好、明确事实、成功经验（本轮用「规则 + 简单 LLM 抽取」，不做 `reflect` 分级）
- **去重**：与已有 Vector Memory 做相似度比对，高于阈值则不重复写入
- **异步**：run 主流程不阻塞；固化失败不影响 run 结果（best-effort）
- **召回**：Plan 节点装配时并行查 `recall()`，top-k 片段注入 `memory_ctx`（附来源，供 LLM 参考）

### 8.4 embedding 接入

- 经 LiteLLM 统一接入 embedding 模型（与 chat 网关一致），抽象 `Embedder`：
  ```python
  class Embedder(Protocol):
      async def embed(self, texts: list[str]) -> list[list[float]]: ...
  ```
- 环境变量 `EMBEDDING_MODEL` + 对应 key；维度在建表时确定（见 §15 待拍板）

## 9. Gateway：多租户 + JWT 鉴权 + 限流

### 9.1 中间件链（`api/middleware.py`）

```
Auth（解析 JWT → user/tenant）→ Tenant（注入 tenant_id）→ RateLimit（令牌桶）→ Trace（生成 trace_id）→ Audit（登录/授权留痕）→ Route
```

### 9.2 JWT 鉴权（`api/security.py`）

- 登录：`POST /v1/auth/login {username, password}` → 校验密码 → 签发 JWT（HS256）
- Token payload：`{"sub": user_id, "tenant_id": ..., "exp": ..., "scope": "api"}`
- **角色不进 token**：每次从 DB/Redis 查（角色变更即时生效，缓存短 TTL 30s）
- 依赖注入 `get_current_user` 返回 `CurrentUser(user_id, tenant_id, roles)`；`get_current_tenant` 返回 tenant_id
- 免鉴权：`/health`、`/v1/auth/login`；其余均需 `Authorization: Bearer <token>`

### 9.3 多租户隔离

- 所有资源行级带 `tenant_id`；查询一律 `WHERE tenant_id = current_tenant`（deps 层统一过滤，杜绝跨租户读取）
- 资源 id 全局唯一（ULID），但访问必须命中本租户；跨租户访问返回 404（不暴露存在性）

### 9.4 限流（令牌桶，Redis）

- Key：`rl:{tenant_id}:{user_id}` 与 `rl:{tenant_id}`（租户级兜底）
- 配置：`RATE_LIMIT_PER_MIN`（默认 60）、`RATE_LIMIT_BURST`（默认 120）
- 超限返回 `429 RATE_LIMITED`（错误格式见 §12.6）

## 10. IAM：RBAC + 资源授权 + 高危审批

### 10.1 内置角色 → 权限映射

| 角色 | 权限点 |
|------|--------|
| `admin` | 全部（含 `role:manage` / `grant:manage` / `user:manage`） |
| `developer` | `agent:*`、`tool:register`、`tool:view`、`skill:register`、`skill:view`、`run:execute`、`run:view` |
| `operator` | `run:execute`、`run:view`、`run:cancel` |
| `viewer` | `agent:view`、`tool:view`、`skill:view`、`run:view` |

### 10.2 资源级授权（Grant）

把「谁能用哪个 Tool/Skill」落成 `grants` 表，三种粒度：

| 粒度 | 示例 |
|------|------|
| 全量授权 | `grant(tool:calculator → 所有用户)`（`principal_type=role, principal_id=viewer` 等） |
| 按角色授权 | `grant(tool:db_query → role:数据分析组)` |
| 按用户授权 | `grant(skill:refund → user:张三)` |

- 默认门槛：`read`（人人可用）/ `write`（需授权）/ `admin`（需授权 + 高危审批）
- 原则：**默认拒绝**、**拒绝优先**（deny 覆盖 allow）、租户内生效

### 10.3 校验流程（`iam/permission_manager.py`）

```python
class PermissionDecision(Enum):
    ALLOW = "allow"
    DENY = "deny"
    REQUIRE_APPROVAL = "require_approval"

async def check(user, action, resource_type, resource_id) -> PermissionDecision:
    # ① 功能权限：user 的角色是否含该 action 的 Permission
    # ② 资源授权：是否有匹配的 Grant（user 或其角色）；deny 优先
    # ③ 高危判定：resource.permission in (write,admin) 或 requires_approval=true
    #    且无本次 run 内已批准的记录 → REQUIRE_APPROVAL
    # 默认拒绝 → DENY
```

### 10.4 高危工具人工确认（HITL-lite，前置审批门）

> ⚠️ **本节已作废（2026-08-26）**：§15 的开放决策已拍板为「执行中挂起」，checkpoint 持久化从 V0.3 前移至 V0.2。
> 实际实现是**运行中暂停 + `AgentRuntime.resume` 同 run 续跑**，以《业务层详细设计.md》§9 与《API文档.md》§4 为准。下文保留仅作决策留痕。

```
POST /v1/agents/{id}/runs（输入含高危工具绑定）
    │
    ▼
Gateway 检查 agent.config.plugins 中是否存在 admin/requires_approval 的工具
    │  存在且未批准
    ▼
run 状态置 awaiting_human，返回 status=awaiting_human（不执行）
    │
人工 POST /v1/runs/{id}/actions {action:"approve", resource_type:"tool", resource_id:"tool_x"}
    │
    ▼
run 记录 approvals += [tool_x]，状态切 running，真正执行
    │（approve 在本次 run 内缓存，后续同工具不再重复确认）
```

- 审批与越权拦截分离：**越权 → 运行中拒绝（§7.2）**；**高危 → 运行前审批（本节）**
- 审批决策全量写 `audit_logs`；`reject` 则 run 直接 `canceled`

## 11. Runtime：SubAgent 调用 + execute 节点改造

### 11.1 AgentState 扩展（`core/state.py`）

```python
class AgentState(TypedDict, total=False):
    # ...V0.1 字段保留...
    plugins: list[dict]        # 装配后的插件引用 [{type, ref, config}]
    memory_ctx: list[dict]     # 召回的长期记忆片段
    subagent_depth: int        # 子 Agent 递归深度（防无限嵌套）
    system_prompt: str | None
    approvals: list[dict]      # 本次 run 已批准的高危资源（透传给 execute 的权限校验）
```

### 11.2 execute 节点分派（`core/nodes/execute.py` 改造）

```python
async def run_execute(state: AgentState, plugin_registry, perm_manager):
    action = state["action"]              # Decide 选择：tool:calculator / skill:refund@1 / "__finish__"
    if action == "__finish__":
        return {}
    plugin = await plugin_registry.resolve(action)
    # 权限校验（越权拦截）
    decision = await perm_manager.check(state["user_id"], "execute", plugin.kind, plugin.manifest.name)
    if decision == PermissionDecision.DENY:
        return {"last_tool_result": f"[denied] 无权调用 {action}", "iteration": state["iteration"] + 1}
    # 按 kind 分派
    if plugin.kind == "skill" and plugin.type == "agent":
        result = await _run_subagent(plugin, state)   # 子 Agent，见 11.3
    else:
        result = await plugin.invoke(ctx, **state["action_input"])
    return {"last_tool_result": result}
```

### 11.3 SubAgent 调用（父-子嵌套，`skills/agent_skill.py`）

- `agent-skill.body = {"agent_ref": "agent_xxx"}`；execute 命中 `agent` 类型时，加载子 Agent 的 config，复用 `run_agent()` 递归跑同一 Runtime 图
- **防递归**：`subagent_depth` 每层 +1，超过 `max_subagent_depth`（默认 3）即终止并回填错误
- **可追溯**：子 Agent 运行写入 `runs` 表（`parent_run_id` 指向父 run），`run_steps` 完整落数据
- 子 Agent 的结果作为工具输出回填父 Agent 的 `last_tool_result`

### 11.4 主循环不变

LangGraph 图结构（plan → decide → execute → observe）不变；变化的是 Decide 的「可选能力」从纯 Tool 变为 Tool + Skill 统一列表，以及 execute 的插件分派。无 checkpointer（V0.3 引入）。

## 13. 关键实现要点与风险

1. **权限校验必须在 execute 前，而非 decide 后**：LLM 可能选一个未授权工具，execute 节点校验兜底（默认拒绝），越权返回错误给 Observe 反思，不抛 500。
2. **插件懒加载与热更新的一致性**：`is_latest` 切换后，缓存按 `ref` 失效重建；已运行的 run 沿用装配时的插件版本，不中途换实现。
3. **子 Agent 防无限递归**：`subagent_depth` 硬限制（默认 3）+ 子 Agent 也走 `max_iterations`/`timeout`，双保险。
4. **多租户隔离是安全红线**：deps 层统一 `tenant_id` 过滤，宁可重复写过滤条件也不留裸查询；跨租户一律 404。
5. **固化异步与去重**：会话固化 best-effort，失败不阻塞 run；重复片段靠相似度阈值去重，避免长期记忆膨胀。
6. **高危审批与 checkpoint 的边界**：V0.2 只做前置审批门；若业务需「执行到一半停下来等确认」，需提前引入 V0.3 checkpoint，本规格不覆盖。
7. **embedding 维度固定**：`vector(1536)` 建表后改维度需重建索引，选型前冻结（§15）。
8. **测试**：`test_iam.py`（RBAC/越权拦截/高危审批）、`test_plugins.py`（四类 Skill 分派 + ref 解析 + 懒加载）、`test_vector_memory.py`（写入/召回/固化去重）、`test_subagent.py`（嵌套 + 防递归）。
