# V0.1 实施规格（Implementation Spec）

> 对应《版本规划.md》V0.1「骨架版」。目标：**一个 Agent 能理解任务、调用工具、产出结果**，跑通最小闭环。
> 技术栈：Python 3.11 + FastAPI + LangGraph + LiteLLM + SQLAlchemy 2.0 + Pydantic v2 + PostgreSQL + Redis。

---

## 1. 范围（做什么 / 不做什么）

**做**：
- 单 Agent 多轮对话 + 工具调用（Plan → Decide → Execute → Observe 主循环）
- Builtin 工具 2-3 个（calculator / http）
- 会话级 Working Brain（Redis 存历史，无长期记忆）
- 同步运行 + SSE 流式事件
- LLM Gateway 抽象 + LiteLLM 单厂商接入

**不做（后续版本）**：
- 鉴权 / 租户隔离 / 权限管理（IAM）（V0.2）
- 插件体系（统一 Plugin 协议）（V0.2）
- Skill Manager（V0.2）
- Cognitive Brain / Memory Graph / Vector Memory（V0.2 起步、V0.3 完整）
- RAG / KG（V0.3）
- checkpoint / Retry / HITL / Pause-Resume（V0.3）
- 可观测 / Console / 评测（V1.0 / V1.1）

## 3. 数据模型 DDL（PostgreSQL）

```sql
-- 工具（Builtin / 后续 http·mcp·custom）
CREATE TABLE tools (
    id            VARCHAR(64)  PRIMARY KEY,
    name          VARCHAR(64)  NOT NULL UNIQUE,
    type          VARCHAR(32)  NOT NULL DEFAULT 'builtin',  -- builtin|http|mcp|custom
    description   TEXT,
    parameters    JSONB        NOT NULL,   -- JSON Schema（供 LLM function calling）
    permission    VARCHAR(16)  NOT NULL DEFAULT 'read',     -- read|write|admin
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);

-- Agent
CREATE TABLE agents (
    id            VARCHAR(64)  PRIMARY KEY,
    tenant_id     VARCHAR(64)  NOT NULL DEFAULT 'default',  -- V0.1 恒为 default，列先占位
    name          VARCHAR(128) NOT NULL,
    version       VARCHAR(32)  NOT NULL DEFAULT '1',
    config        JSONB        NOT NULL,   -- 见 §5 AgentConfig
    status        VARCHAR(16)  NOT NULL DEFAULT 'active',
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_agents_tenant ON agents (tenant_id);

-- Agent ↔ Tool 多对多
CREATE TABLE agent_tools (
    agent_id      VARCHAR(64)  NOT NULL REFERENCES agents(id) ON DELETE CASCADE,
    tool_id       VARCHAR(64)  NOT NULL REFERENCES tools(id)  ON DELETE CASCADE,
    PRIMARY KEY (agent_id, tool_id)
);

-- 运行实例
CREATE TABLE runs (
    id            VARCHAR(64)  PRIMARY KEY,
    agent_id      VARCHAR(64)  NOT NULL REFERENCES agents(id),
    tenant_id     VARCHAR(64)  NOT NULL DEFAULT 'default',
    user_id       VARCHAR(64),
    input         TEXT         NOT NULL,
    status        VARCHAR(32)  NOT NULL,  -- queued|running|completed|failed|canceled
    result        TEXT,
    error         TEXT,
    trace_id      VARCHAR(64),
    token_usage   JSONB,                  -- {"prompt":x,"completion":y,"total":z}
    cost          NUMERIC(12,6) NOT NULL DEFAULT 0,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    started_at    TIMESTAMPTZ,
    finished_at   TIMESTAMPTZ
);
CREATE INDEX idx_runs_agent  ON runs (agent_id, created_at DESC);
CREATE INDEX idx_runs_tenant ON runs (tenant_id, created_at DESC);

-- 执行步骤（支撑 DAG 可视化，V0.1 先落数据）
CREATE TABLE run_steps (
    id            VARCHAR(64)  PRIMARY KEY,
    run_id        VARCHAR(64)  NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
    seq           INT          NOT NULL,
    node          VARCHAR(32)  NOT NULL,  -- plan|decide|execute|observe
    action        VARCHAR(128),           -- 工具名（execute 节点）
    input         JSONB,
    output        JSONB,
    status        VARCHAR(16)  NOT NULL,  -- running|success|failed|skipped
    latency_ms    INT,
    token_usage   JSONB,
    error         TEXT,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_run_steps_run ON run_steps (run_id, seq);
```

> 主键 `id` 用 ULID/雪花（时间有序），由应用生成。`tenant_id` 在 V0.1 恒为 `'default'`，提前占位避免后续迁移。

## 4. Agent 配置 Schema（`agents.config` 的 JSONB 内容）

```jsonc
{
  "system_prompt": "你是一个通用助手，遇到计算类问题调用 calculator 工具。",
  "model": "deepseek-chat",          // 默认模型（国产 DeepSeek；V0.1 单模型，可换 Qwen/GLM）
  "runtime": {
    "max_iterations": 20,               // Decide→Execute 循环上限，防死循环
    "timeout_seconds": 120,             // 全局超时
    "cost_budget_usd": null             // 成本上限（null = 不限，V0.1 不用）
  },
  "tools": ["tool_calculator", "tool_http"],   // 绑定工具 id 列表
  "memory": {
    "enabled": true,
    "window_size": 20                   // Working Brain 保留最近 N 条消息
  }
}
```

> 注：V0.1 用 `tools` 字段绑定工具；V0.2 起统一为 `plugins` 数组（含 skill/knowledge/model 等，见《技术方案设计》4.12），本字段平滑迁移。

## 6. Runtime 状态机

### 6.1 AgentState（`core/state.py`）

```python
from typing import TypedDict, NotRequired

class PlanStep(TypedDict):
    id: int
    description: str
    status: str                      # pending|running|done|failed

class AgentState(TypedDict):
    agent_id: str
    task: str                        # 用户输入
    messages: list[dict]             # 会话历史（含 system + user + assistant + tool）
    plan: list[PlanStep]             # Plan 节点产出
    action: str | None               # Decide 节点选择：tool 名 或 "__finish__"
    action_input: dict | None        # 工具入参
    last_tool_result: str | None     # 最近一次工具输出
    iteration: int                   # 已执行工具次数
    status: str                      # running|completed|failed
    result: str | None               # 最终答案
    error: str | None
```

### 6.2 节点输入输出契约

| 节点 | 输入（读 State） | 输出（写 State） | 逻辑 |
|------|------------------|------------------|------|
| **plan** | task, messages | plan | LLM 将任务拆为步骤列表 |
| **decide** | task, plan, messages, last_tool_result | action, action_input | LLM 选择：调用哪个工具 / 完成并给答案 |
| **execute** | action, action_input | last_tool_result | 从 ToolRegistry 取工具并执行 |
| **observe** | last_tool_result, plan, iteration | messages, iteration, status, result | 回填结果；判断是否继续 / 结束 |

### 6.3 主循环（`core/graph.py`）

```python
from langgraph.graph import StateGraph, END

def should_continue(state: AgentState) -> str:
    if state["iteration"] >= state["max_iterations"]:
        return "finish"
    if state["action"] == "__finish__":
        return "finish"
    return "execute"

g = StateGraph(AgentState)
g.add_node("plan", plan_node)
g.add_node("decide", decide_node)
g.add_node("execute", execute_node)
g.add_node("observe", observe_node)
g.set_entry_point("plan")
g.add_edge("plan", "decide")
g.add_edge("decide", "execute")            # 由 should_continue 决定是否跳 finish
g.add_conditional_edges("observe", should_continue, {"execute": "decide", "finish": END})
g.add_edge("execute", "observe")
```

> V0.1 无 checkpointer；会话历史由 Working Brain（Redis）在节点间透传，状态在内存中随图运行。checkpoint 属 V0.3。

## 7. LLM Gateway 统一抽象

### 7.1 数据结构（`llm/base.py`）

```python
class Usage(BaseModel):
    prompt_tokens: int = 0
    completion_tokens: int = 0
    total_tokens: int = 0

class ToolCall(BaseModel):
    id: str
    name: str
    arguments: dict

class LLMResponse(BaseModel):
    content: str | None
    tool_calls: list[ToolCall] = []
    usage: Usage

class LLMGateway(Protocol):
    async def chat(
        self,
        messages: list[dict],
        model: str,
        tools: list[dict] | None = None,
    ) -> LLMResponse: ...
```

### 7.2 LiteLLM 实现（`llm/litellm_gateway.py`）

```python
import litellm

class LiteLLMGateway:
    async def chat(self, messages, model, tools=None) -> LLMResponse:
        kwargs = {"model": model, "messages": messages}
        if tools:
            kwargs["tools"] = [{"type": "function", "function": t} for t in tools]
        resp = await litellm.acompletion(**kwargs)
        msg = resp.choices[0].message
        return LLMResponse(
            content=msg.content,
            tool_calls=[ToolCall(id=tc.id, name=tc.function.name,
                                 arguments=json.loads(tc.function.arguments))
                        for tc in (msg.tool_calls or [])],
            usage=Usage(**resp.usage.model_dump()),
        )
```

**模型决策（已定）**：V0.1 默认用国产模型 `deepseek-chat`（DeepSeek，OpenAI 兼容、工具调用稳定），经 LiteLLM 接入，环境变量 `DEEPSEEK_API_KEY`；后续可换 Qwen/GLM 或做分层路由。

## 8. API 接口契约（字段级）

### 8.1 创建运行

`POST /v1/agents/{agent_id}/runs`

```jsonc
// 请求
{ "input": "帮我算 3*8 再加 100", "stream": false, "user_id": "u_1" }

// 响应 200（同步完成）
{
  "run_id": "run_01J...",
  "agent_id": "agent_cs",
  "status": "completed",            // queued|running|completed|failed
  "result": "3*8+100 = 124",
  "steps": [
    {"seq": 1, "node": "plan",     "output": {"plan": ["计算 3*8", "加 100"]}},
    {"seq": 2, "node": "decide",   "output": {"action": "calculator", "action_input": {"expression": "3*8+100"}}},
    {"seq": 3, "node": "execute",  "output": {"result": "124"}},
    {"seq": 4, "node": "observe",  "output": {"result": "3*8+100 = 124"}}
  ],
  "usage": {"prompt_tokens": 320, "completion_tokens": 88, "total_tokens": 408},
  "created_at": "2026-08-19T10:00:00Z",
  "finished_at": "2026-08-19T10:00:03Z"
}
```

### 8.2 查询运行

`GET /v1/runs/{run_id}` → 结构与 8.1 响应一致（`status` 可能为 `running`，此时 `result` 为 null）。

### 8.3 SSE 流式事件

`GET /v1/runs/{run_id}/stream`（或 8.1 传 `stream: true`）

```
event: run.started
data: {"run_id":"run_01J...","status":"running"}

event: step.completed
data: {"seq":3,"node":"execute","action":"calculator","output":{"result":"124"},"latency_ms":120}

event: run.completed
data: {"run_id":"run_01J...","status":"completed","result":"124","usage":{...}}
```

**事件类型（V0.1）**：`run.started` / `step.completed` / `run.completed` / `run.failed`

### 8.4 统一错误格式

```jsonc
{
  "error": {
    "code": "INVALID_ARGUMENT",     // 见 8.5
    "message": "input 不能为空",
    "trace_id": "trace_01J..."
  }
}
```

### 8.5 错误码

| code | HTTP | 场景 |
|------|------|------|
| INVALID_ARGUMENT | 400 | 参数缺失/非法 |
| RESOURCE_NOT_FOUND | 404 | agent/run 不存在 |
| MODEL_UNAVAILABLE | 503 | LLM 调用失败/超时 |
| TOOL_EXECUTION_FAILED | 500 | 工具执行异常 |
| TIMEOUT | 504 | 运行超时 |

## 9. Working Brain（V0.1 简版）

- 存储：Redis `Key = wb:{session_id}:messages`，存最近 `window_size` 条消息的 JSON 列表，TTL 24h
- 接口：`get_history(session_id)` / `append(session_id, message)`
- 不做固化/召回/遗忘（V0.2 起）

## 10. 关键实现要点与风险

1. **防死循环**：`max_iterations`（默认 20）+ `timeout_seconds` 双保险，任一触顶即 `finish`。
2. **工具入参解析**：LLM 返回的 `arguments` 是 JSON 字符串，需容错解析（失败时把错误回传给 LLM 重试一次）。
3. **Redis 与 DB 一致性**：Working Brain 是易失缓存，`runs`/`run_steps` 是真相源；缓存丢失不影响结果追溯。
4. **异步长任务**：V0.1 同步返回即可；若单个运行 >30s，改为 `202 Accepted` + 轮询/SSE（预留 `status=queued`）。
5. **测试**：`test_runtime.py` 用 mock LLM 验证循环收敛；`test_api.py` 端到端验工具调用。
