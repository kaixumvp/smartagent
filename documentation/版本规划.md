# SmartAgent 平台 · 版本规划（Roadmap）

> 依据《技术方案设计.md》拆分。原则：**每个版本都是可独立验证、可交付的增量**，MVP 先行，能力 → 可靠 → 生产 → 评测逐步演进。

---

## 一、版本总览

| 版本 | 主题 | 目标 | 核心交付 | 建议周期 |
|------|------|------|----------|----------|
| V0.1 | 骨架 | 打通最小闭环 | 单 Agent 对话 + 工具调用 | 2-3 周 |
| V0.2 | 能力 | 可组装、可复用 | 插件体系 + Skill/Tool 注册、多租户 + 权限、长期记忆起步 | 3-4 周 |
| V0.3 | 知识与可靠 | 有知识、可可靠执行 | RAG+KG、Cognitive Brain、Retry/HITL/Pause | 4-5 周 |
| V1.0 | 生产 | 可观测、可干预、可运维 | 全链路可观测 + Console + 安全 + K8s | 4-5 周 |
| V1.1 | 评测与智能 | 可评估、可优化 | Evaluation + Playground + 成本优化 | 3-4 周 |
| V2.0 | 进阶（远期） | 多智能体协同 | 多 Agent 协作、微调 | 待定 |

---

## 二、各版本详细说明

### V0.1 骨架版（最小闭环）

**目标**：证明核心循环可行——一个 Agent 能理解任务、调用工具、产出结果。

**范围**：

| 模块 | 本期实现 |
|------|----------|
| LLM Gateway | LiteLLM 接入单厂商，基础调用（无路由/fallback） |
| Agent Runtime | LangGraph 主循环（Plan/Decide/Execute/Observe），无 checkpoint |
| Tool Manager | Builtin 工具 2-3 个（计算器/搜索/HTTP），JSON Schema 声明 |
| Working Brain | Redis 会话态，仅当前会话上下文 |
| Gateway | 单用户 HTTP API，无鉴权/租户 |

**关键交付**：`POST /v1/agents/{id}/runs` 跑通一个带工具调用的 Agent。

**验收标准**：
- 多轮对话 + 至少 1 个工具调用成功
- 有迭代上限与超时，不会死循环

**依赖**：无（纯验证技术栈可行性，避免过度设计）

---

### V0.2 能力版（可组装、可复用）

**目标**：从「写死一个 Agent」到「业务方组装 Agent」，平台初具通用性。

**范围**：

| 模块 | 本期实现 |
|------|----------|
| 插件体系 | 统一 Plugin 协议 + manifest 标准 + 生命周期 + 插件 SDK（Skill/Tool/Knowledge 统一接入） |
| Skill Manager | Skill 注册/版本/绑定，四种 Skill 形态（prompt/function/flow/agent） |
| Tool Manager | 扩展 MCP 工具 + HTTP(OpenAPI) 工具 + 权限管控（最小权限 + 高危 HITL 确认） |
| Brain | Working Brain 完整 + 长期记忆起步（Vector Memory 基础写入/召回 + 会话固化） |
| Gateway | 多租户隔离 + JWT 鉴权 + 限流 |
| 权限管理（IAM） | RBAC（用户/角色/权限）+ 资源级授权（Skill/Tool 给用户/角色授权）+ 高危 HITL |
| Runtime | SubAgent 调用（父-子嵌套） |
| 工程架构 | 单体 → 分层双包：业务层 + Agent 框架层（smartagent-core）分离，Ports & Adapters |

**关键交付**：业务方通过「注册 Skill + 配置 Agent」上线一个新场景，不改框架核心。

**验收标准**：
- 新增一个垂直场景 ≤ 1 天（纯配置）
- 工具越权调用被拦截，高危操作触发人工确认
- 跨会话能召回历史偏好

**依赖**：V0.1

---

### V0.3 知识与可靠性版

**目标**：Agent 有外挂知识、长任务可靠执行、可被干预。

**范围**：

| 模块 | 本期实现 |
|------|----------|
| Knowledge | RAG 完整流水线（摄取/切块/embedding/检索/Rerank）+ KG 起步（PG 邻接表） |
| Brain | Cognitive Brain 完整：Memory Graph + Vector Memory + 固化/遗忘/元记忆 + 知识回退（Brain 不全 → Knowledge） |
| Workflow Engine | Retry（退避/熔断）+ Pause/Resume + HITL + checkpoint 持久化 + 异步执行 |
| Storage | 向量库（pgvector）+ 图库（PG 邻接表） |

**关键交付**：
- 长任务可重试、可暂停/恢复、可人工介入
- Brain 知识不全时自动回退 Knowledge 补全并沉淀

**验收标准**：
- 任务中断后可从 checkpoint 恢复（幂等）
- 引用可溯源（RAG 附来源）
- 知识回退命中率有量化统计

**依赖**：V0.2

---

### V1.0 生产版（可观测、可干预、可运维）

**目标**：达到生产 SLA，Agent 从黑盒变白盒。

**范围**：

| 模块 | 本期实现 |
|------|----------|
| Observability | OTel 全链路 + Prometheus/Grafana + Langfuse + Loki 日志 |
| Agent Console | 第一版：监测看板 + 执行跟踪可视化（DAG/时间线/下钻）+ 暂停/恢复/取消控制 |
| 安全 | mTLS、数据脱敏、PII 检测、Prompt 注入防护、审计留痕、Vault 密钥 |
| 部署 | K8s + Helm + HPA + 灰度发布 + 高可用（PG 主从、Redis 哨兵） |
| Gateway | 完整协议适配（SSE/WebSocket）、限流熔断、多厂商路由 fallback |

**关键交付**：生产级可上线的平台，控制台可实时监测与干预。

**验收标准**：
- 满足生产 SLA（TTFT < 1s、可用性 99.9%）
- 一次运行可全链路回溯（trace_id）
- 故障可在控制台定位并干预

**依赖**：V0.3

---

### V1.1 评测与智能化版

**目标**：Agent 迭代有量化依据，质量劣化可阻断。

**范围**：

| 模块 | 本期实现 |
|------|----------|
| Evaluation | 离线 Golden Set + LLM-as-Judge + 在线反馈 + A/B |
| Agent Console | 完善：Playground 测试台 + 版本对比 + 单步调试 |
| 成本优化 | 模型分级路由（简单任务小模型）、缓存命中复用 |
| Knowledge | KG 升级 Neo4j（规模化） |

**关键交付**：评测闭环 + 测试台，版本发布前有回归保障。

**验收标准**：
- 质量劣化版本能被回归测试阻断发布
- 成本较 V1.0 下降（有量化目标）

**依赖**：V1.0

---

### V2.0 进阶版（远期 / 可选）

- 多智能体协同（多 Agent 组队、任务分配、协商）
- 更强的规划与反思机制
- 自有模型微调 / RLHF
- 复杂 KG 推理（图神经网络等）

## 五、关键原则

1. **每版可交付**：每个版本结束都要有可演示、可验证的产物，不留「半成品」。
2. **MVP 先行**：V0.1 验证技术栈与核心循环可行性，避免前期过度设计。
3. **能力前置、可靠后置**：先让 Agent 有通用能力（V0.2），再上可靠性（V0.3）；可观测在进生产前补齐（V1.0）。
4. **评测最后**：评测依赖真实运行数据，放 V1.1 更务实。
5. **接口先行稳定**：V0.2 起稳定 Gateway/Runtime 对外契约，后续版本不破坏兼容。
6. **框架与业务分层**：Agent 框架层（smartagent-core）与业务层分离，业务依赖框架、框架不依赖业务；能力端口（Ports）由框架定义、业务实现（Adapters），保证框架可独立发布与复用。
