# 核心设计图：Brain 记忆结构 + 执行跟踪 DAG

> 本文档细化《技术方案设计.md》的 4.3（Brain）与 4.10（Agent Console）两张关键图，作为后端与前端实现的「图规范」。
> 符号约定：`●` 数据/节点，`─►` 同步数据流，`┄►` 异步/事件流，`◇` 决策点。
> 分层归属：第一部分（Brain 记忆结构）属 **Agent 框架层**（memory 子系统，`WorkingMemory`/`LongTermMemory` 端口）；第二部分（执行跟踪 DAG）属 **业务层**（Console，消费框架层 `EventSink` 产出的事件）。详见《技术方案设计.md》3.1。

# 第一部分 · Brain 记忆结构图

## 1.1 总体结构（分层 + 数据流）

```
                 ┌──────────────────────────────────────┐
                 │      Persona（人格 / 自我 · 配置层）      │
                 │   角色 · 风格 · 目标 · 价值观 · 边界        │
                 └───────────────────┬──────────────────┘
                                     │ 每次会话注入（稳定身份）
                                     ▼
      ┌────────────────────────────────────────────────────────┐
      │              Memory Manager（统一门面）                   │
      │   write · consolidate · query · forget · reflect        │
      │   sufficiency(召回充分度)                                 │
      └──────┬──────────────────────────────────┬──────────────┘
             │ 写入/固化                          │ 召回(query)
             ▼                                   ▼
   ┌───────────────────────┐        ┌────────────────────────────────┐
   │    Working Brain      │  固化   │        Cognitive Brain         │
   │   （工作记忆 · 短期）    │ ┄┄┄┄┄► │      （认知记忆 · 长期）          │
   │                       │        │                                │
   │  · 存储：Redis         │        │  ┌──────────────────────────┐  │
   │  · 范围：Session 级    │        │  │  Memory Graph（记忆图谱）  │  │
   │  · 内容：当前任务       │        │  │  结构化 · Concept—Relation │  │
   │          中间推理       │        │  │  精确关系 · 多跳推理        │  │
   │          临时变量       │        │  └──────────────────────────┘  │
   │          注意力焦点     │        │  ┌──────────────────────────┐  │
   │  · 特征：全量注入·TTL   │        │  │  Vector Memory（向量记忆） │  │
   └───────────────────────┘        │  │  语义 · embedding 索引      │  │
                                    │  │  模糊语义 · 泛化            │  │
                                    │  └──────────────────────────┘  │
                                    └────────────────────────────────┘
      ┌────────────────────────────────────────────────────────┐
      │        Meta-memory（元记忆 · 贯穿各层，非独立存储）          │
      │   每条记忆附带：来源 · 时间戳 · 访问次数 · 置信度 · 重要性     │
      └────────────────────────────────────────────────────────┘
```

**存储映射**：

| 层 | 存储 | 生命周期 |
|----|------|----------|
| Persona | PostgreSQL（配置表） | 长期 |
| Working Brain | Redis（Session Key） | 单次会话，TTL |
| Memory Graph | Neo4j（或 PG 邻接表） | 长期 |
| Vector Memory | pgvector / Milvus | 长期 |
| Meta-memory | 内嵌于上述条目字段 | 随主数据 |

## 1.2 四个数据流操作

| 操作 | 触发 | 路径 | 说明 |
|------|------|------|------|
| **write 写入** | 会话中实时 | Runtime ─► Working Brain（Redis） | 中间推理/变量/焦点，TTL 释放 |
| **consolidate 固化** | 会话结束异步(Celery) | Working ─► Cognitive | 结构化抽取→Memory Graph；语义 embedding→Vector Memory |
| **query 召回** | Plan/Decide 阶段 | Cognitive/Working ─► Runtime | 并行查 Graph + Vector，融合注入上下文 |
| **forget 遗忘** | 衰减/显式删除 | 各层级联清理 | 时间衰减 + 访问加权 + 重要性 + 合规删除 |

## 1.3 Memory Graph 内部结构

```
         ┌──────────────────┐          ┌──────────────────┐
         │ Concept（概念节点） │ ─偏好──► │ Concept（概念节点） │
         │  id: user_A       │          │  id: style_short │
         │  type: user       │          │  type: preference │
         │  name: 张三        │          │  name: 简洁回答    │
         │  attrs: {…}       │          │  attrs: {…}       │
         └────────┬─────────┘          └──────────────────┘
                  │ 任职于
                  ▼
         ┌──────────────────┐
         │ Concept          │
         │  id: org_X       │
         │  type: company   │
         └──────────────────┘
```

**节点（Concept）**：`id`、`type`（user/entity/event/preference/rule…）、`name`、`attributes(JSON)`
**边（Relation）**：`source`、`target`、`relation_type`（偏好/任职/做过/类似…）、`weight`、`source_meta`

**查询能力**：单跳（`张三 偏好 ?`）、多跳（`张三 任职 ? 的 竞品 是 ?`）、路径推理。
**存储**：起步 PG 邻接表（`memory_graph_node` / `memory_graph_edge`），规模化切 Neo4j（Cypher 同构）。

## 1.4 Vector Memory 内部结构

```
  写入：内容 ─► embedding 模型 ─► 向量 + 元数据
  索引：HNSW（pgvector）/ IVF（Milvus）

  ┌─────────────────────────────────────────────────────────┐
  │ Vector Memory Entry                                      │
  │  id · tenant/user · content · embedding(1536d)           │
  │  importance(0-1) · confidence(0-1)                       │
  │  access_count · last_access · ttl                        │
  └─────────────────────────────────────────────────────────┘
```

**召回流程**：`query 文本 ─► embedding ─► top-k 相似 ─► 按 importance+confidence+新鲜度 重排 ─► 截断`
**相似度阈值**：默认 0.75，低于即判定「不全」触发知识回退（见 1.6）。

## 1.5 记忆生命周期（写 → 固化 → 召回 → 遗忘）

```
  ┌────────┐   固化(异步)   ┌──────────────┐   召回    ┌────────┐
  │ Working │ ┄┄┄┄┄┄┄┄┄┄► │  Cognitive   │ ────────► │ Runtime│
  │  Brain  │               │  (Graph+Vec)  │  top-k    │  Plan  │
  └────┬───┘                └──────┬───────┘           └────────┘
       │                           │
       │ 衰减/过期                   │ 遗忘(衰减·访问·重要性·删除)
       ▼                           ▼
     TTL 释放                  级联清理 + 审计留痕
```

- **固化触发**：会话结束 / 任务成功 / 用户纠错（高价值信号）
- **遗忘触发**：时间衰减（`importance × e^(-Δt/τ)`）、低频访问降权、显式删除（合规）

## 1.6 检索与知识回退流程（Brain 不全 → Knowledge）

```
  Runtime 需要某类知识
        │
        ▼
  ┌───────────────────────────────────────────────┐
  │ ① 并行检索 Brain                                │
  │    Working(全量) + Memory Graph(关系)          │
  │    + Vector Memory(语义 top-k)                 │
  └───────────────────────┬───────────────────────┘
                          ▼
              ┌───────────────────────┐
              │ ② sufficiency() 评估    │
              │  相似度 / 图命中 / 置信度 │
              │  / 新鲜度（四阈值）       │
              └──────────┬────────────┘
                    充分   │   不全/低置信
              ┌───────────┘────────────┐
              ▼                        ▼
      直接用 Brain 记忆         ③ 检索 Knowledge（RAG + KG）
                                        │
                                        ▼
                              ④ 补全注入上下文（附来源）
                                        │
                              ⑤（可选）沉淀回 Brain
                                 有效→固化 Graph/Vec，学习闭环
```

# 第二部分 · 执行跟踪 DAG 交互稿

## 2.1 控制台整体布局（线框）

```
┌────────────────────────────────────────────────────────────────────────┐
│ 控制台 │ Agent: 客服助手 v1.2 │ Run #8842 │ ●运行中 │ [⏸暂停][▶恢复][✕取消] │ ← 顶栏
├───────────────┬────────────────────────────────────────┬───────────────┤
│  运行列表       │            DAG 执行图（中心）            │  节点详情面板    │
│               │                                        │               │
│  #8842 ●      │   [Plan]──►[Decide]──►[Execute:tool]    │  节点：Execute │
│  #8841 ✓      │               │          │             │  状态：成功     │
│  #8840 ✗      │               ▼          ▼             │  工具：search  │
│  #8839 ⏸      │           [Observe]──►[Decide]         │  入参：{…}     │
│               │                                        │  出参：{…}     │
│               │                                        │  耗时：1.2s    │
│               │                                        │  token：842    │
├───────────────┴────────────────────────────────────────┴───────────────┤
│ 时间线 ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁  │ ← 底栏
└────────────────────────────────────────────────────────────────────────┘
```

- **顶栏**：Agent 名称/版本、Run ID、状态徽章、控制按钮（暂停/恢复/取消，二次确认）
- **左栏**：运行列表（状态点 + 摘要），点击切换
- **中心**：执行 DAG（主视图）
- **右栏**：选中节点详情（入参/出参/prompt/工具结果/报错）
- **底栏**：时间线（可拖动回放）

## 2.2 节点类型与图标

| 节点 | 图标 | 含义 | 可下钻内容 |
|------|------|------|-----------|
| Plan | 📋 | 任务拆解/生成步骤 | 生成的 plan 文本 |
| Decide | 🧭 | 选择工具/Skill/SubAgent | 候选工具、选择理由 |
| Execute | ⚙️ | 调用 Tool/Skill/SubAgent | 工具名、入参、出参、耗时、token |
| Observe | 👁 | 结果回填 + 反思 | 反思结论、是否继续 |
| HITL | 👤 | 人工决策挂起 | 等待的决策、选项 |

## 2.3 节点状态与配色

| 状态 | 颜色 | 线型 | 说明 |
|------|------|------|------|
| pending 待执行 | 灰 | 虚线 | 尚未运行 |
| running 进行中 | 蓝 | 实线 + 脉冲 | 当前节点 |
| success 成功 | 绿 | 实线 | 完成 |
| failed 失败 | 红 | 实线 | 出错（可点开看堆栈） |
| paused 已暂停 | 琥珀 | 粗实线 | 暂停中，等待恢复 |
| awaiting_human 待人工 | 橙 | 实线 + 闪烁 | HITL 挂起 |
| skipped 跳过 | 浅灰 | 点线 | 未执行/被跳过 |

## 2.4 交互行为规范

| 交互 | 行为 |
|------|------|
| **Hover 节点** | 浮层提示：节点类型 + 状态 + 一句话摘要 |
| **点击节点** | 右侧详情面板展开该节点完整信息（入参/出参/prompt/工具结果/错误堆栈） |
| **状态实时更新** | 通过 SSE 推送，DAG 节点状态/颜色实时变化，无需刷新 |
| **回放 Replay** | 底部时间线拖动，按事件流回放决策过程 |
| **断点/单步** | 测试台（Playground）模式下可设断点、单步执行、注入工具结果 |
| **下钻链路** | 点击 SubAgent 节点可跳转到子 Agent 的 DAG（多智能体嵌套） |

## 2.6 控制交互闭环（暂停 / 恢复 / 取消）

```
  控制台点击「暂停」
        │ POST /v1/runs/{id}/pause
        ▼
  Gateway 下发指令 ─► Runtime 当前节点完成后挂起（checkpoint）
        │ 状态置 paused
        ▼
  SSE 推送「run.paused」─► 控制台节点转琥珀色、按钮切「恢复」
        │
  控制台点击「恢复」──► POST /v1/runs/{id}/resume ─► 从 checkpoint 续跑
        │
  SSE 推送「run.resumed」─► 节点转蓝色继续
```

- **取消**：`POST /v1/runs/{id}/cancel`，停止后续节点、回收资源，状态 `canceled`
- **安全**：控制动作二次确认 + 审计（谁在何时暂停/恢复了哪个 Run）
