# Ouroboros · 版本规划（Roadmap）

> 本文档从平台《SmartAgent 平台 · 版本规划》中**拆出框架层部分**。原平台规划描述的是「业务层 + 框架层」合并的单体演进；Ouroboros 已独立成包（`pip install ouroboros`），因此按自身语义化版本演进。
>
> **范围**：仅 `ouroboros` 包自身的能力。业务层的 HTTP 入口、多租户、鉴权数据、持久化、RAG 流水线实现、Console、K8s 部署**不在本文档范围**，见平台文档《业务层详细设计.md》。
>
> 当前版本：**v1.1.0**（对应平台 V1.1 的框架层切片）

---

## 〇、拆分边界：什么归框架，什么归宿主

平台规划里的每个模块都被这条线切成两半——**机制（Mechanism）归框架，策略与 IO（Policy & IO）归宿主**。

| 平台模块 | Ouroboros（框架）负责 | 宿主（业务层）负责 |
|----------|----------------------|-------------------|
| LLM Gateway | `LLMGateway` 协议 + LiteLLM 默认实现 + 路由/fallback 装饰器 | 密钥管理、厂商配额、成本核算 |
| Agent Runtime | 运行循环、状态机、迭代/深度/超时控制 | Run 记录落库、异步任务调度 |
| 插件体系 | `Plugin` 协议、`PluginManifest`、`PluginRegistry`、ref 解析 | 从 DB 装配插件（`db_plugin_loader`） |
| Skill Manager | 四形态 Skill 的**执行** | Skill 的注册 / 版本 / 绑定 CRUD |
| Tool Manager | Builtin / MCP / HTTP(OpenAPI) 工具的**执行** | 工具的租户级配置与凭据 |
| Brain / 记忆 | Working Brain、Consolidator、`LongTermMemory` 端口、召回编排 | pgvector 实现、DB 会话 |
| Knowledge | `Knowledge` / `Retriever` 端口 + `kind="knowledge"` 插件形态 | RAG 摄取/切块/embedding/Rerank 流水线、KG 存储 |
| Workflow / 可靠性 | Retry、熔断、超时、Pause/Resume 机制、`Checkpointer` 端口 | checkpoint 持久化、HITL 审批单据与通知 |
| 权限（IAM） | `check_permission()` 纯逻辑 + `PermissionChecker` 端口 | RBAC/Grant 数据加载、`PermissionContext` 构建 |
| 事件 | `RuntimeEvent` 数据模型 + `EventSink` 端口 | SSE/WebSocket 传输、事件落库 |
| Observability | span/metric 埋点（仅依赖 `opentelemetry-api`） | Collector、Prometheus、Grafana、Langfuse |
| Evaluation | 确定性重放、`Judge` 端口 | Golden Set 管理、A/B、报表 |
| Console / 部署 | — | 全部 |

> 判据：**框架能否在没有数据库、没有 HTTP、没有租户概念的情况下单测通过**。能，就归框架。

## 二、各版本详细说明

### v0.1 骨架版 ✅

**目标**：证明 `Plan → Decide → Execute → Observe` 循环可行。

| 模块 | 交付内容 |
|------|----------|
| `llm/` | `LLMGateway` 协议 + `LiteLLMGateway`（单厂商）+ `LLMResponse`/`ToolCall`/`Usage` |
| `core/` | LangGraph 图装配 `build_graph` + 四节点 + `AgentState` |
| `tools/` | `BaseTool`/`ToolResult` + `calculator`(AST 白名单) / `http` |

**验收**：多轮对话 + ≥1 次工具调用成功；有迭代上限，不死循环。

---

### v0.2 能力版 ✅（当前 0.2.0）

**目标**：从「写死一个 Agent」到「宿主组装 Agent」，并从平台单体中**独立成可发布的包**。

| 模块 | 交付内容 |
|------|----------|
| `plugins/` | `Plugin` 协议 + `PluginManifest` + `InvokeContext` + `ToolAsPlugin` 适配 + `PluginRegistry`（裸名 / `kind:name@version` / `function_name` 三键索引）+ ref 解析 |
| `skills/` | 四形态 `prompt` / `function` / `flow` / `agent` + `SkillManager.build()` + `skill_` 前缀命名空间隔离 |
| `tools/` | MCP 客户端（JSON-RPC 2.0 over streamable HTTP）+ HTTP(OpenAPI) 工具生成 |
| `memory/` | `WorkingBrain`（Redis 滑窗 + TTL）+ `Consolidator`（规则抽取 + 0.85 相似度去重）+ `MemoryManager` 门面 |
| `ports.py` | `check_permission()` 纯逻辑 + `PermissionChecker` / `WorkingMemory` / `LongTermMemory` / `MemoryEntry` |
| `core/nodes/execute.py` | **执行前**强制授权（不信任 LLM 的选择） |
| `events/` | 运行时事件（`run.started` / `step.completed` / `run.completed` / `run.failed` / `run.awaiting_human` / `run.approved` / `run.rejected`） |
| `log.py` | `ouroboros` 命名空间 + `NullHandler`，框架不自行配置 handler |
| 工程 | 从 `smartagent` 单体拆出，src layout，独立 `pyproject.toml`，55 个单测全部 fake 依赖（无 Redis/LLM/DB） |

**验收**：宿主不改框架核心，仅「注册 Skill/Tool + 配置 Agent」即可上线新场景；越权调用被 `execute` 拦截；高危插件返回待审批。

---

### v0.3 收口与可靠版 ✅

**目标**：把 v0.2 遗留的架构债还掉（端口收口、门面收口、传输解耦），并让长任务真正**可重试、可暂停、可介入**。

| 方向 | 交付内容 |
|------|----------|
| **端口收口** | 把散落的 `LLMGateway`(`llm/base.py`)、`Embedder`(`llm/embedder.py`)、`Plugin`(`plugins/base.py`) 全部收进 `ports.py`；补 `EventSink` / `SubagentRunner` / `FlowRunner` / `Checkpointer` 端口。目标：`import ouroboros.ports` 一处看全框架↔宿主契约 |
| **`AgentRuntime` 门面** | `AgentRuntime.run(definition, task, context, deps) -> RunResult`；引入 `AgentDefinition` / `RunContext` / `RuntimeConfig` / `RuntimeDeps` / `Step` / `RunResult` 强类型，取代当前的裸 `dict` 出入参 |
| **事件解耦** | `events/sse.py` → `events/events.py`：框架只产出 `RuntimeEvent` 对象，**SSE 序列化下沉宿主**；`EventSink` 端口取代 `on_step(dict)` 回调 |
| **可靠执行** | 节点级 Retry（指数退避）+ 熔断；`RuntimeConfig.timeout_seconds` 真正生效；`max_subagent_depth` 真正强制（当前仅有注释与状态字段，无强制） |
| **暂停 / 恢复 / HITL** | 接入 LangGraph checkpointer（经 `Checkpointer` 端口，持久化留宿主）；高危审批从「返回 `[approval required]` 字符串后继续跑」升级为真正 `pause → awaiting_human → resume(approvals)` 同 run 续跑 |
| **记忆增强** | Memory Graph 结构、`reflect` 重要度评分、遗忘策略、`sufficiency` 充分性判定；知识不足时回退 Knowledge 端口并回写沉淀 |
| **知识端口** | `Knowledge` / `Retriever` 端口 + `kind="knowledge"` 插件形态（RAG 流水线实现由宿主提供） |

**兼容性**：`build_graph` / `run_agent` 保留一层 deprecated shim，v1.0 移除。

**验收**：
- 任一 run 可从 checkpoint 恢复，且恢复幂等
- 高危插件触发 `awaiting_human`，`resume` 后在**同一 run** 内继续
- 工具瞬时失败自动重试；run 超时可中止；子 Agent 递归超深被拒
- 框架↔宿主的全部契约集中在 `ports.py`

**依赖**：v0.2

---

### v0.4 可观测与安全版 ✅

**目标**：框架侧具备生产可观测性，补齐 v0.2 明确标注为「非安全边界」的执行面。

| 方向 | 交付内容 |
|------|----------|
| **链路追踪** | 每节点 / 每插件调用产出 OTel span，`trace_id` 经 `InvokeContext` 全程透传；框架只依赖 `opentelemetry-api`，且为**可选依赖**（未安装时降级为 no-op） |
| **指标** | 迭代数、工具时延、token 用量、失败率经 `Metrics` 端口暴露，宿主接 Prometheus |
| **执行沙箱** | `FunctionSkill` 当前用 `exec` + 受限 builtins，代码内已注明「不是安全边界」——本版落地子进程/容器沙箱，或改为显式 opt-in 的可信模式 |
| **注入防护** | Prompt 注入基础防护（工具结果与用户输入的边界标注）；敏感信息脱敏范围从日志扩展到事件与 span |
| **韧性** | 多厂商路由 + fallback（以 `LLMGateway` 装饰器实现，不污染核心）；`tool_call` 解析容错与结构化输出兜底 |
| **并发** | 单轮 LLM 返回多个 `tool_calls` 时并行执行 |

**验收**：一次 run 的全链路 span 完整可回溯；FunctionSkill 逃逸测试通过；主厂商故障自动 fallback 且被 span 记录。

**依赖**：v0.3

### v1.0 API 冻结 · 正式发布 ✅

**目标**：给出稳定性承诺，宿主可放心升级。

- 公共 API 面冻结：显式导出清单（`__init__.py`）+ 弃用策略（弃用需跨一个 minor）
- 移除 v0.3 引入的 deprecated shim（`build_graph` / `run_agent`）
- 类型完备（`py.typed`）、CHANGELOG、文档站、PyPI 正式发布
- 兼容矩阵：Python 3.11 – 3.14

**验收**：宿主升级 minor 版本无需改代码；破坏性变更只出现在 major。

**依赖**：v0.4

### v1.1 评测与成本版 ✅

| 方向 | 交付内容 |

## 三、v0.3 交付与剩余差距

v0.3 已交付（对应下方矩阵 ● 项），将 v0.2 的 8 项架构债清零：

| 原差距 | 交付 |
|--------|------|
| 裸 `dict` 出入参 | `AgentRuntime.run/resume` + `AgentDefinition`/`RunContext`/`RuntimeConfig`/`RuntimeDeps`/`Step`/`RunResult` 强类型 |
| 端口分散 | `LLMGateway`/`Embedder`/`Plugin`/`EventSink`/`SubagentRunner`/`FlowRunner`/`Checkpointer`/`Knowledge`/`Retriever` 全部收进 `ports.py`（旧模块 re-export 保持兼容） |
| SSE 侵入框架 | `events/events.py` 只产出 `RuntimeEvent`；`sse.py` 降级为 deprecated shim |
| `on_step(dict)` | `EventSink` 端口 + `RuntimeEvent` 事件模型 |
| 无超时/深度 | `RuntimeConfig.timeout_seconds`（`asyncio.timeout`）+ `max_subagent_depth` 在 execute 前强制 |
| 审批死路 | `Checkpointer` 端口 + `resume()`：`awaiting_human` 暂停 → 授权后同 run 续跑 |
| 无 Retry/熔断 | `core/resilience.py`：`RetryPolicy`（指数退避）+ `CircuitBreaker` |
| 无知识端口 | `Knowledge`/`Retriever` 端口 + `KnowledgePlugin`（`kind="knowledge"`）；记忆不足时回退知识并回写 |

**简化项**：记忆增强交付了 `reflect` 规则评分、遗忘阈值（`Consolidator.importance_threshold`）、`sufficiency` 充分性判定与知识回退；**Memory Graph（图结构）未交付**，留待后续版本。

v0.4 已交付（对应矩阵 ● 项）：

| 原差距 | 交付 |
|--------|------|
| `FunctionSkill` 无沙箱 | `function_skill.py` 默认**子进程沙箱**（受限 builtins + 超时），`sandbox="inline"` 显式 opt-in；逃逸测试通过 |
| 无 span / metric | `observability/`：`Tracer`（可选 `opentelemetry-api`，no-op 降级）+ `Metrics` 端口；`trace_id` 经 `InvokeContext` 全程透传 |
| `LiteLLMGateway` 单厂商 | `llm/routing.py`：`FallbackLLMGateway`（多厂商 failover）+ `FaultTolerantGateway`（结构化输出兜底） |
| 注入 / 脱敏 | `security/`：`wrap_tool_result` + `TOOL_RESULT_GUARD`（工具结果边界标注）+ `Redactor`（密钥脱敏覆盖事件） |
| 单 `tool_call` | `decide`/`execute`/`observe` 支持多 `tool_calls` 并行执行（`asyncio.gather`） |

> `opentelemetry-api` 为可选依赖（`pip install ouroboros[observability]`）；未安装时追踪降级为 no-op，包仍可离线安装使用。

**剩余**：v2.0 多智能体（多 Agent 协同、反思机制）见 §二。

v1.0 已交付：删除 `build_graph`/`run_agent` shim、`py.typed`、`CHANGELOG.md`、公共 API 面冻结（`__all__` 显式导出）、Python 3.11–3.14 兼容矩阵。

v1.1 已交付：`llm/replay.py`（record/replay 确定性重放）、`Judge`/`JudgeVerdict` 端口 + `evaluation/`（`GoldenSet`/`run_evaluation`/`HeuristicJudge`）、`llm/cost.py`（`CachingGateway`/`TieredRouter`/`TokenBudget`）+ `RuntimeConfig.max_total_tokens`。

## 五、与平台版本的对齐

```
平台   V0.1 ──► V0.2 ──► V0.3 ──────► V1.0 ──────────► V1.1 ──► V2.0
                                        │
Ouroboros v0.1 ─► v0.2 ─► v0.3 ─► v0.4 ─┴─► v1.0 ────► v1.1 ─► v2.0
```

- 框架版本**领先或齐平**于平台版本：平台某版依赖的框架能力，必须在该平台版本启动前发布。
- 平台 V1.0 需要框架的两步（v0.4 可观测 + v1.0 API 冻结），因为「生产可用」= 能看见 + 不会变。
- 框架可独立于平台发布 patch 版本。

## 六、演进原则

1. **框架不反向依赖宿主**：不 import 宿主的 HTTP / DB / 配置 / 租户概念；新增能力先问「这条能不能在纯内存单测里跑通」。
2. **端口先行**：需要外部 IO 的能力，一律先在 `ports.py` 定义 Protocol，再考虑要不要给默认实现。
3. **默认可跑**：每个端口尽量配一个零配置的默认/降级实现（如 `HashEmbedder` 之于 `LiteLLMEmbedder`），保证 `pip install` 后能直接跑通示例。
4. **容错收敛**：LLM 失败退化为单步计划、空输出即收尾、迭代上限兜底——新增节点必须给出兜底路径。
5. **测试无外部依赖**：Redis / LLM / DB 一律 fake，`poetry run pytest` 在无网环境必须绿。
6. **SemVer 与弃用**：v1.0 起破坏性变更只进 major；弃用至少跨一个 minor 并在 CHANGELOG 标注。
